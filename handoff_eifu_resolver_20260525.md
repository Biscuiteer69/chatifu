## Resolver Behavior

- stdlib-only
- preserves e-IFU flow:
  - GET /welcome
  - POST HCP + language
  - POST terms acknowledgement
  - GET /search-document-metadata/{catalog_number}
- explicitly detects HTTP 200 welcome/HCP/terms/session-gate pages
- exact_catalog and model_match rows are stored as found
- broad search_result rows are stored as candidate_broad
- not_found, session_gate, auth_failed, init_failed, http_error, network_error, and timeout are distinct statuses
- stale catalog-level document_url IS NULL outcome rows are deleted after document rows are persisted
- writes are idempotent through partial unique indexes and upsert/fallback logic
- warnings are emitted if unique partial indexes cannot be created because of duplicate dirty data

## Explicit Safety/Storage Statement

- Resolver does not download PDFs.
- Resolver does not request viewpdf/viewpdf-iframe URLs as PDF downloads.
- Resolver does not store PDF bytes.
- Resolver does not store IFU/PDF body text.
- Resolver stores only metadata/link rows.

## Remaining Risks

- ensure_ifu_links_table() assumes a preexisting ifu_links table has original base columns; malformed/very old partial tables could fail before freshness migration.
- True concurrent writes rely on unique partial indexes. If a dirty DB skips those indexes because duplicates exist, concurrency protection is weaker.
- Gate detection remains heuristic because e-IFU markup can change.
- Session-flow tests use offline fake opener responses, not live e-IFU integration tests.
